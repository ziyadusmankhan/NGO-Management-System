# Beginner testing guide: Tasks, Meetings and Reports

Use separate browser profiles when testing different users. Never use real personal information in test notes.

## 1. Prepare permissions

1. Sign in as Administrator.
2. Open **Users & Roles → Manage Roles**.
3. Confirm a coordinator role has **View Tasks**, **Manage Tasks**, **View Meetings**, **Manage Meetings**, **View Reports** and **Generate Reports**.
4. Give a second active user **View Tasks** and **View Meetings**.

Pass: the second user can read the sections but cannot create, edit, finalize, archive or export.

## 2. Create and assign a task

1. Open **Operations → Tasks → Create task**.
2. Enter a clear title, choose High priority, assign the second user and select a due date next week.
3. Optionally link an active committee or project.
4. Save.

Pass: a number such as `TSK-00001` appears, the assignee is correct, and the task is visible on the dashboard when due within 14 days.

## 3. Test progress rules

1. Open the task and try **Completed** with 90%. It must fail.
2. Try **In progress** with 100%. It must fail.
3. Save **In progress** with 50% and add an update.
4. Finish with **Completed**, 100% and completion notes.

Pass: each valid change is retained; invalid combinations show a clear error. The task may now be archived and restored.

## 4. Schedule a meeting

1. Open **Operations → Meetings → Schedule meeting**.
2. Enter a title, date, time, location and agenda.
3. Invite at least two users and set quorum to 2.
4. Save.

Pass: a number such as `MTG-00001` appears and only invited users are listed.

## 5. Record minutes and action items

1. Open the scheduled meeting.
2. Select only one attendee and try to finalize minutes. It must fail because quorum is 2.
3. Select both attendees, enter minutes and a decision.
4. Add an action-item title, assignee, due date and priority, then finalize.

Pass: the meeting becomes Held, actual attendance appears, and the action item opens as a linked numbered task. A second finalization attempt is blocked.

## 6. Cancel and archive a meeting

1. Create another scheduled meeting.
2. Cancel it and enter a reason.
3. Archive it, enable **Include archived** in the meeting list, then restore it.

Pass: the reason and record history remain available; no record is permanently deleted.

## 7. Generate an Operations report

1. Open **Records → Reports**.
2. Choose **Operations Activity** and a period containing your test records.
3. Generate the report.

Pass: task and meeting counts come from the records you created. Note the report number.

## 8. Confirm snapshot behavior

1. Record another task after generating the report.
2. Reopen the earlier report.
3. Generate a new report for the same period.

Pass: the first report retains its original figures; the new report contains the new task.

## 9. Print and XLSX

1. Open a generated report and choose **Print / Save PDF**.
2. Use the browser Print dialog and save a PDF.
3. Download XLSX and open it in Excel or LibreOffice.

Pass: the report reference, period, metrics and breakdown agree across the screen, print view and spreadsheet.

## 10. Check access and audit

1. Sign in as a user with Reports permissions but without Finance access.
2. Confirm Financial Summary is absent and cannot be generated by changing the request manually.
3. As an auditor, open **Records → Audit Trail** and filter module `operations` or `reports`.

Pass: source-module permissions protect report metadata and content. Task, meeting, report-generation and export events identify the actor and reference without exposing encrypted notes.

## Automated verification

From the project directory run:

    php artisan test --compact tests/Feature/OperationsAndReportsTest.php
    php artisan test --compact

The first command checks the new workflow. The second confirms existing Welfare, Finance, Qard, Business, Projects, Procurement, Audit and Documents behavior still passes.
